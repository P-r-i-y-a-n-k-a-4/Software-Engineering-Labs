# Student Club Event Ticketing & Budget Portal

**PES University – Department of Computer Science and Engineering**

**Problem Statement #10 – Campus & Academic Operations**

## Project Overview

The Student Club Event Ticketing & Budget Portal is a proposed system designed to streamline campus event management by integrating event proposal submission, university budget approvals, attendee registration, and secure QR-code ticketing.

The system aims to improve administrative efficiency, financial accountability, ticket security, and the overall event experience for student clubs and attendees.

## Project Objectives

- Define and analyse the system's functional and non-functional requirements.
- Model system interactions and workflows using software engineering techniques.
- Plan and track development activities using Agile project management practices.
- Evaluate and justify a suitable software architecture based on system requirements.
- Address scalability, performance, fault isolation, and security.

## Key Stakeholders

- **Club Lead:** Submits event proposals and requests budgets.
- **Campus Admin / Gate Staff:** Oversees event administration and validates tickets.
- **Faculty Coordinator:** Reviews event budget proposals.
- **Finance Office:** Verifies budget requests.
- **Dean:** Provides final budget approval.
- **Attendee:** Registers for approved events and presents tickets for entry.

## Lab Submissions

This repository contains the documentation for three Software Engineering lab activities related to the Student Club Event Ticketing & Budget Portal.

### Lab 1 – Requirements Engineering & UML Use-Case Modelling

Focuses on requirements specification, acceptance criteria, prioritisation, UML use-case modelling, and use-case flow documentation.

### Lab 2 – Agile Project Management

Focuses on sprint planning and tracking using Jira, including epics, user stories, story point assignments, the active sprint board, the burndown chart, and sprint reflection.

### Lab 3 – Architecture Selection & Justification

Focuses on selecting and justifying a suitable architecture for the portal. Microservices architecture is selected to support independent scaling, fault isolation, security boundaries, and the performance requirements of the ticketing service.
